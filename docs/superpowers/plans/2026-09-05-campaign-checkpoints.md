# Campaign, checkpoints and sprint implementation plan

**Goal:** Ship Lunacrust 1.1.0 with multiple named save checkpoints, an eight-world survival campaign with an ending, accessible sprinting, and verified Windows/macOS/Linux installers.

**Architecture:** A pure campaign state machine controls ordered unlocks and inventory costs. The shell owns transitions and one atomic `campaign-current` envelope containing campaign progress and all visited world snapshots. Named checkpoints store independent copies of that envelope or a creative world. Existing creative and legacy saves remain separate. No checkpoint restore or travel mutates a connected guest's own campaign.

**Tech stack:** Existing JavaScript/Three.js/Electron, plain Node tests, Playwright and native GitHub Actions.

## Contracts and sequence

- [x] Campaign domain: `CAMPAIGN_STAGES`, `createCampaign`, `normalizeCampaign`, `stageFor`, `canVisit`, `arrive`, `requirementsFor`, `repairRelay`, `nextDestination` in `app/js/campaign.js`. Route: earth, luna, mars, venus, europa, io, titan, jupiter. Each relay consumes locally obtainable materials, unlocks the next leg and appends original story text. Completion requires all eight relays and visits. Test locks, atomic costs, corrupted saves and real terrain/recipe reachability.
- [x] Checkpoint persistence: `saveCheckpoint(name,snapshot)`, `listCheckpoints`, `loadCheckpoint`, `renameCheckpoint`, `deleteCheckpoint` in `app/js/checkpoints.js`. IDs are unique, names are plain text, max 50 with explicit refusal instead of eviction. A campaign envelope has `{kind:'campaign',version:1,campaign,worlds,savedAt}`. Checkpoint operations cannot overwrite autosaves, creative worlds or guest characters. Test real temporary desktop saves as well as browser storage.
- [x] Sprint input: ground Shift or Ctrl sprints forward; C sneaks. Flying keeps Shift descent and Ctrl boost. Pause, blur, release, death and pointer unlock clear held input and sprint state. Test actual displacement, no backward/sneak boost and survival exertion.
- [x] Shell integration: survival begins on Earth, locked destinations stay inspectable but cannot be launched, visited worlds retain edits, and travel carries current inventory and suit equipment without reclaiming stale inventory from old world snapshots. Save current state before transition and keep recoverable state on write/load failure. Creative remains unrestricted. A mission log shows story, material requirements, relay action, next flight and final ending.
- [x] Checkpoint UI: menu/pause library, named creation, load with replacement confirmation, rename and delete with confirmation, empty/corrupt/full/error states. Named checkpoints remain unchanged by autosave and restore. Connected guests cannot replace a host world. Host travel/restore explicitly ends the current LAN session and guests can rejoin.
- [x] Browser verification: fresh survival locks, creative access, real mission buttons/costs/travel through all stages to ending, autosave/reload, checkpoint independence/rollback/delete, save failure, new-campaign cancellation and sprint movement. Inspect screenshots at 1440x900 and the minimum window; run the installed web-game skill client and existing affected UI/LAN probes.
- [ ] Release: bump app/package protocol identity to 1.1.0, update guides and runtime verifier to start at the campaign's Earth destination. Run deterministic suite and native installer CI. Download only successful native artifacts, verify source/assets and checksums, inspect DMGs, create source archive and prepare release attachments. Signing remains contingent on already requested credentials; do not claim unsigned artifacts are notarized.

Parallel ownership: checkpoint persistence, campaign domain and sprint are separate bounded agents; root owns shell/UI, integration, tests and release. A clean feature branch isolates this work from the prior candidate. Final integration checks cover all three changes together before building.
